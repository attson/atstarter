# Rootyard Global Chinese and English i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add complete, runtime-switchable Simplified Chinese and English localization to every Rootyard-owned frontend surface, with a persisted system-language preference and no change to native diagnostic output.

**Architecture:** Persist a `system | zh-CN | en` preference in the existing App Settings aggregate and use a tiny namespaced localStorage cache only to choose the locale before Vue mounts. A focused `frontend/src/i18n` module owns preference normalization, system resolution, `vue-i18n`, document metadata, and message catalogs; components translate stable domain codes at render time, while raw Git, Docker, Shell, filesystem, and backend error details remain untouched.

**Tech Stack:** Go 1.23, Wails v2 generated bindings, Vue 3.2, `vue-i18n` 9.14.5, Node test runner, Vite, VitePress.

**Spec:** `docs/superpowers/specs/2026-11-27-global-i18n-design.md`

## Global Constraints

- Support exactly `system`, `zh-CN`, and `en` as persisted language-preference values.
- Resolve any system locale beginning with `zh` to `zh-CN`; resolve every other system locale to `en`.
- Use English as the runtime fallback locale and keep English and Chinese recursive message-key sets identical.
- `config.json.settings.language` is authoritative after load; localStorage key `rootyard.settings.language` is only a synchronous startup cache.
- Apply a saved language only after `SaveAppSettings` succeeds; canceling or a failed save must not change the active preference.
- While preference is `system`, react to the browser `languagechange` event and keep `<html lang>` equal to the effective locale.
- Translate every Rootyard-owned visible string, dialog string, input hint, tooltip, title, and accessibility label under `frontend/src`.
- Never translate project/group names, paths, commands, branch/container names, logs, config keys, native domain values, or raw third-party/backend error details.
- Helpers return stable codes, keys, or structured data; Vue components call `t()` at render time so open views update immediately.
- Keep the Projects / Containers / Environments navigation order, geometry, fixed controls, truncation, and responsive behavior unchanged.
- Use `/Users/attson/sdk/go1.23.12/bin/go` for Go and Wails generation commands in this worktree.
- Preserve the public site's real-`App.vue` demo by installing the same i18n instance in the VitePress app.

- [ ] **Step 3: Implement the pure locale and cache layer**

Use exact public values and an injectable storage boundary:

```js
export const LANGUAGE_PREFERENCES = Object.freeze(['system', 'zh-CN', 'en'])
export const LANGUAGE_CACHE_KEY = 'rootyard.settings.language'

export function normalizeLanguagePreference(value) {
  return LANGUAGE_PREFERENCES.includes(value) ? value : 'system'
}

export function resolveSystemLocale(language = '') {
  return String(language).toLowerCase().startsWith('zh') ? 'zh-CN' : 'en'
}

export function resolveEffectiveLocale(preference, language = '') {
  const normalized = normalizeLanguagePreference(preference)
  return normalized === 'system' ? resolveSystemLocale(language) : normalized
}
```

`readCachedLanguagePreference(storage = globalThis.localStorage)` catches both storage lookup and `getItem`; `writeCachedLanguagePreference` catches lookup and `setItem`. Neither function may throw.
